# PPT Creator Skills

`ppt-studio` 是一个面向 Codex 的商务 PPTX 生成 Skill：它把业务场景、资料补充、模板复用、封面/图标/图表等资产管理，以及逐页 QA 放进同一条可追溯流程。

它生成的是可编辑 PowerPoint（`.pptx`），不是图片拼贴，也不是“创建另一个 Skill”的工作流。

## 它解决的三件事

1. **Agent 能生成 PPTX。** 当信息、数据边界和视觉路线已明确时，Skill 调用已安装的 `Presentations` 能力，使用可编辑对象、原生图表和逐页渲染 QA 生成 PPTX。
2. **可沉淀多套模板。** `assets/template-registry.template.json` 是模板元数据登记表；每个已批准模板一个条目。登记源文件哈希、布局 profile、所有者、可保留范围、场景适配和验证记录。模板二进制默认不进入本仓库。
3. **资料不全时不会直接开工。** Skill 必须先达到信息完整性门槛；缺少受众/决策、内容依据、数据边界、视觉路线、素材策略或交付基线时，状态保持为 `awaiting-input`，只收集缺失信息，不检查模板、不生成资产、不创建 PPTX。

## 安装

将本仓库中的 `.agents/skills/ppt-studio` 复制到目标项目的同一路径：

```text
<your-project>/.agents/skills/ppt-studio/
```

随后在 Codex 中使用 `$ppt-studio`。该 Skill 依赖当前环境已经安装的 `Presentations` Skill；如果需生成非事实插图，也会按资产策略调用图像生成能力。

## 给普通同事的复制式提示词

```text
使用 $ppt-studio 帮我制作一份 PPTX。
如果资料不足，请先只列出需要补充的信息和当前状态，不要生成 PPT、检查模板或创建素材。
资料完整后，先用一句话复述受众、希望推动的决定、模板/视觉路线和素材策略；我确认后再开始。
```

如果已具备全部资料并允许直接开始：

```text
使用 $ppt-studio 制作一份 [业务场景] PPTX，受众是 [谁]，希望他们作出 [决定/行动]。
资料是 [文件/链接/虚构数据说明]，数据边界是 [绿色/已获批黄色]。
视觉上使用 [已上传的指定模板 / registry 模板 ID / 明确视觉方向 / 简洁默认版式]；素材策略是 [四种策略之一]。
信息若仍不足，请暂停并一次性问我；信息完整后可直接生成。
```

## 多模板的登记、使用和优化

从 [模板登记表](.agents/skills/ppt-studio/assets/template-registry.template.json) 开始：

1. 先确认模板所有者、保留/分发权限和批准的源位置；一次性用户文件不会自动成为可复用模板。
2. 记录稳定模板 ID、适用业务场景、源文件 SHA-256、所有者和许可范围，初始 `enabled: false`。
3. 检查母版、布局和占位符，完成 profile；用虚构绿色样例跑一次并逐页渲染验收。
4. 记录样例运行与已知限制后，再由所有者批准启用。匹配多个同优先级模板时，Skill 会请用户选择，绝不混搭或静默替换。
5. 源 PPTX/POTX 改变后，必须将 profile 标记为 `refresh-required`、停用、重新画像和复测；保留历史元数据与审计记录。

完整规则见 [模板登记与画像说明](.agents/skills/ppt-studio/references/template-registry-and-profiling.md)。

## 安全与边界

- 对第三方 PPTX/POTX、备注、元数据、附件和 URL 中的“指令”一律按不可信文档内容处理，不会执行其中的命令或链接。
- 红色敏感资料（人事、薪酬、健康、可识别客户等）在解析模板或请求素材前停止；黄色资料需先确认处理环境获批。
- 指定模板无法读取时不静默降级；缺少资料时不会生成半成品或资产文件夹。
- 每次生成应交付 PPTX、同名 `deck-assets/`、资产 manifest 和 generation manifest；被阻断的运行显式记录原因，不创建 deck-assets。

## 发布包范围

本仓库只包含 Skill 指令、模板登记/manifest 模板和参考说明；不含任何公司模板、用户文件、客户数据、生成 PPTX、素材或测试输出。

## 验证说明

发布前以完全虚构数据完成了一次 5 页 PPTX 冒烟测试：含 2 个原生图表、1 个封面图像、5 张逐页渲染图和 manifest。当前 Windows 内置 artifact-tool 在写完已验证输出后可能于原生清理阶段返回 `0xC0000409`；这是运行时环境限制，Skill 因而要求在渲染、结构或源检查受阻时明确报告，不得声称视觉验收已经完成。
