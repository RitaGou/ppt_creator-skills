# 调用契约

## 最小输入

普通用户只需提供：

```text
用「[模板包名称]」生成 PPT；内容：[主题、简要内容、提纲或材料]。
```

例如：

```text
用「市场调研·活力手账」生成 PPT；内容：XR 直播间市场调研，面向内部领导。
```

模板包名称必须通过模板库的 `index.json` 解析到已验证版本。内容依据至少说明主题、已有内容、提纲或材料中的一种；当前对话中已经给出的主题同样有效。未提供大框架时，使用包内 `framework.defaultOutline`。

如果内容依据暂缺，但调用者在本轮明确提出了边界冲突或“每次确认”，先只处理那一个边界问题；回答后再根据默认大框架和对话上下文判断是否仍需要内容依据。不要一次列出内容、页数、图片等多个问题。

## 可选覆盖

用户可在最小输入之后，任选其一补充：

- `大框架：[章节方向]`：只改变这次内容结构。
- `页数：[N]`：正整数；作为 `pageFramework` 的本次页数覆盖，只有该类别可变或已确认时才生效。
- `边界：[保持、可变或每次确认的自然语言要求]`：只覆盖提到的类别。
- `每页不超过 [N] 字`、语言或交付形式：作为本次运行参数。

未提到的项目继续使用模板包默认值。

## 单一澄清文案

| 情况 | 只问这一句 |
| --- | --- |
| 名称不唯一 | `「[名称]」有多个版本；本次用哪一个版本？` |
| 版本未发布校验 | `这个模板包版本未完成发布校验；请指定已验证版本或重新发布模板包。` |
| 没有内容依据 | `请给我一个主题、简要内容、提纲或材料，任选一种即可。` |
| 默认框架无法适用 | `这个模板包没有可用的默认大框架；请用一句话给出本次要讲的章节方向。` |
| 类别为每次确认 | `本次 [用户明确提到的对象或类别] 是保持还是可变？`；例如：`本次封面图是保持还是可变？` |
| 同类要求矛盾 | `封面图同时被要求保持和替换；本次以哪一种为准？` |
| 超出明确边界 | `本次请求会改变 [类别]，而当前边界不允许；要将该类别改为可变吗？` |

## 追问优先级

同一轮可能同时存在多个缺口时，只问优先级最高的一项，然后重新评估：

1. 模板包不存在、名称/版本不唯一或未完成发布校验；
2. 同一类别的直接冲突；
3. 调用者本轮明确设置为“每次确认”的类别；
4. 模板包默认继承的“每次确认”类别；
5. 缺少内容依据；
6. 超出明确边界的请求。

一次只提出当前阻塞的一个问题；回答后继续，不追加逐页字段表单。
